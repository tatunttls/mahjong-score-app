麻雀成績記録・記録保護版（2026-10-10）

公開リポジトリ tatunttls/mahjong-score-app の main を基に改良しています。
日付別の対局、日付メモ、レート、個人成績、スワイプ切り替えを維持しています。
今回消えた記録の復旧は行いません。

変更した点
・全対局を一括で上書きする保存を廃止し、変更した項目を履歴として追加します。
・同時に別の対局や別の項目を編集しても、互いの記録は消しません。
・入力中の共有更新は履歴に保持し、入力が落ち着いてから画面に反映します。
・空の共有データを受信しても端末内の履歴を消しません。
・削除はごみ箱への移動に変え、戻すことができます。一括削除や完全削除はありません。
・最新100件の変更履歴から、変更した項目を取り消せます。全履歴は保存されています。
・入力ごとに端末内へ保存します。通信失敗時は未送信の履歴を保持して再送します。
・複数タブの入力も、別々の履歴IDで保存するため上書きしません。
・バックアップのJSONファイルを書き出し、同じ成績表に読み込めます。
・保存失敗、容量不足、読めない履歴は画面上に表示します。

本番への反映には、以下の両方が必要です

1. Firebaseの保護設定を適用
   https://console.firebase.google.com/project/mahjong-score-e6bd4/firestore/rules
   で Cloud Firestore → ルールを開き、このフォルダの firestore.rules の内容を設定して公開します。
   他の用途のルールがある場合は、それを確認して必要な部分を保ったうえで適用してください。
   古い「allow read, write: if true;」や全パスを許可するルールが残ると、
   新しい禁止ルールだけを追加しても上書き・削除を防げません。

   この設定は、新保存先 mahjongScoreAppsV11/default/events の履歴を
   「読取り・新規作成のみ」にし、変更と削除を禁止します。
   旧保存先 mahjongScoreApps の書込みも禁止し、旧版のタブからの保存を止めます。
   対象は成績表ID default です。別の成績表IDを使う際は、ルールも合わせて変更してください。

2. GitHubの変更提案を取り込み、GitHub Pagesの公開完了後に全員が再読み込み
   公開リポジトリの変更提案を main に取り込みます。
   ファイルで差し替える場合は次の8ファイルをリポジトリ直下に配置します。
   index.html / style.css / script.js / firebase-config.js / header-chu.png /
   record-store.js / safe-sync.js / README.txt
   Firebase設定は既存のものを維持しています。

   公開後にテスト対局を1件入力し、画面上部が「共有に保存済み」になること、
   別端末にも現れること、ごみ箱への移動と復元ができることを確認してください。
   未送信や共有保存失敗の表示がある間は、共有側へ保存できていません。
   再読み込み後も端末に入力は保持しますが、ブラウザデータの削除はしないでください。

既存データと保護の範囲
・旧保存先と旧ブラウザ保存領域は読み込み・上書きしません。今回は復旧・自動移行をしません。
・旧版から新しい保存先へ変更しているため、旧版と改良版を混在させて使わないでください。
・同じ項目を同時編集した場合は、履歴の順序で表示内容を決めます。
  両方の入力を履歴に残し、「取り消す」から以前の内容に戻せます。
  オフライン中の同じ項目への入力が共有側の新しい履歴と競合する場合も、履歴は失いません。
・端末内の履歴はブラウザデータを消すと失われます。端末外にJSONバックアップを保管してください。
・Firebaseルールは通常のアプリからの履歴変更・削除を拒否します。
  Firebase管理者の操作、Admin SDK、プロジェクト削除までは防げません。
・従来のURL共有方式を維持しています。URLを知る人は履歴を閲覧・新規入力できます。
  誤操作した変更も履歴は残ります。利用者を制限する認証は今回追加していません。
・履歴は入力ごとに増えます。Firebaseの読取り・書込み回数と端末容量を使用します。
  多人数・大量利用では、履歴の保管方式と認証を別途拡張してください。

検証
・node tests/storage.test.cjs：隔離した保存領域・Firebase代替で17項目を検証。
・npm install → npm run test:rules：Firebaseエミュレータで保護ルールの許可・拒否を検証。
  Node.js 24とJava 21が必要です。テスト用 demo プロジェクト以外へ接続しません。
・GitHub Actionsにも同じテストを用意しています。本番データには書き込みません。
